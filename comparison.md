# Сравнительный анализ ChatGPT и Claude для Docs Translator CLI

## 10. Методология сравнения ИИ-инструментов

Сравнение проводилось по одинаковой схеме для обеих нейросетей.

### 10.1. Этапы проверки

1. Передача одинакового ТЗ в ChatGPT и Claude.
2. Получение архива проекта от каждой нейросети.
3. Сохранение промптов, ответов, времени и проблем.
4. Распаковка проектов.
5. Проверка структуры проекта.
6. Установка зависимостей через `uv sync`.
7. Запуск unit-тестов через `uv run pytest`.
8. Проверка покрытия тестами.
9. Проверка CLI-команд через `uv run docstrans ...`.
10. Проверка REST-интеграции через локальный LibreTranslate.
11. Проверка качества кода через `ruff check .`.
12. Проверка форматирования через `ruff format --check .`.
13. Анализ README, `pyproject.toml`, структуры и готовности к GitHub.
14. Сравнение по критериям преподавателя.

### 10.2. Критерии сравнения

Использовались критерии из задания:

- понимание контекста;
- качество кода;
- поддержка диалога;
- скорость ответа;
- обработка ошибок;
- креативность решений;
- документирование;
- производительность;
- соответствие ТЗ;
- работоспособность;
- тестирование;
- качество README;
- удобство публикации на GitHub.

SIM105 Use contextlib.suppress(Exception) instead of try-except-pass

Проблемный фрагмент:

```python
try:
    self.close()
except Exception:
    pass
```

Исправление:

```python
from contextlib import suppress

with suppress(Exception):
    self.close()
```

## 16. Главные практические выводы

1. Подробное ТЗ оказалось ключевым фактором успеха. Обе нейросети смогли реализовать проект потому, что задача была заранее формализована: команды, REST endpoints, структура, тесты, конфигурация и логирование были описаны явно.

2. Нельзя доверять заявлениям нейросети о прохождении тестов без локальной проверки. ChatGPT указал, что `ruff` и тесты прошли, но первый архив не собирался через `uv sync`, а позднее был найден один lint-дефект.

3. `uv` удобен для воспроизводимой проверки проекта. Команды `uv sync`, `uv run pytest`, `uv run ruff check .` и `uv run docstrans ...` позволяют быстро понять, действительно ли архив рабочий.

4. REST API — самая рискованная внешняя зависимость. Публичный LibreTranslate может требовать ключ или оплату, поэтому локальный LibreTranslate оказался практичным решением для демонстрации и тестирования.

5. Unit-тесты обязательно должны мокировать REST API. Обе версии используют тесты без реальных HTTP-запросов, что делает тестирование стабильным.

6. Форматирование Markdown при машинном переводе — отдельная сложная проблема. Даже если команда `translate-file` работает, качество сохранения Markdown-разметки требует дополнительных тестов на реальных документах.

7. Для GitHub-публикации нужно очищать архивы от мусора: `.pytest_cache`, `.ruff_cache`, `__pycache__`, случайные директории вроде `{src`, локальные DB и реальные `.env` файлы.

## 17. Рекомендации по промпт-инжинирингу

1. Перед генерацией кода нужно сначала сделать подробное ТЗ. Формулировка «сделай CLI» недостаточна; нужны команды, аргументы, API, структура, тесты, ошибки и критерии приёмки.

2. В промпте нужно явно требовать не только код, но и проверку:

```text
Перед выдачей архива обязательно выполни:
uv sync
uv run pytest
uv run ruff check .
uv run ruff format --check .
uv run docstrans --help
```

3. Нужно требовать, чтобы нейросеть не включала в архив служебные файлы:

```text
Не включай в архив .venv, __pycache__, .pytest_cache, .ruff_cache, локальные DB, .env с секретами.
```

4. После первой генерации нужно давать нейросети реальные логи ошибок, а не пересказывать проблему своими словами. На примере ChatGPT это сработало: после передачи `run_log.md` packaging был исправлен.

5. Для проверки REST API нужно заранее определить режим демонстрации: внешний ключ или локальный сервер. В данном проекте надёжнее использовать локальный LibreTranslate.

## 18. Рекомендации по будущему развитию проекта

Функциональность проекта достаточна для практической работы, но для реального использования можно улучшить следующие части:

1. Добавить поддержку DeepL API или другого качественного нейросетевого переводчика.
2. Добавить выбор provider через config: `libretranslate`, `deepl`, `mock`.
3. Улучшить защиту Markdown-разметки, чтобы placeholder-токены никогда не попадали в итоговый файл.
4. Добавить интеграционные тесты с локальным LibreTranslate через Docker.
5. Добавить команду `history-clear` с подтверждением.
6. Добавить импорт/экспорт глоссария.
7. Добавить `--dry-run` для `translate-file`.
8. Добавить GitHub Actions workflow для автоматического запуска `pytest` и `ruff`.
